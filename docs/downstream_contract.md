# Downstream contract

Consumers must pin a release ID and manifest hash, then read published artifacts only: `security_master`, `symbol_history`, `company_name_history`, `isin_history`, `issuer_master`, `listing_episodes`, `daily_prices_raw`, `daily_prices_adjusted`, `corporate_actions`, `trading_calendar`, `trading_status`, `trading_status_intervals`, `active_universe_daily`, `liquidity_features`, `research_universe_monthly`, `required_research_security`, `unresolved_observed_trading`, and `terminal_events`.

`required_research_security` is the Phase 2 quality boundary. It contains securities that enter monthly `LIQUID_V1` or monthly Top-750 liquidity scope and carries date range, rank, liquidity, identity, adjustment, instrument, and status evidence. Downstream consumers can use it to identify which securities must stay inside the high-confidence review boundary without scanning every monthly snapshot.

The stable interfaces are `resolve_symbol(symbol, as_of_date)`, `company_name_at(issuer_id, as_of_date)`, `isin_at(security_id, as_of_date)`, `history(security_id, start, end)`, `adjusted_history(security_id, start, end)`, `active_on(as_of_date)`, `profile_on(as_of_date, "LIQUID_V1")`, `eligible_on(as_of_date, ...)`, `ranked_liquid_on(as_of_date, n, metric=...)`, `status_on(as_of_date)`, `observation_status(security_id, as_of_date)`, `sessions_between(start, end)`, `terminal_recovery_scenarios(security_id)`, and `terminal_event_resolution_queue_for_holdings(security_ids)`. `profile_on()` returns rows with `profile_id`, `profile_version`, `as_of_date`, `eligibility_result`, and `eligibility_reason_codes`. `observation_status()` returns `NO_MARKET_SESSION`, `SECURITY_NOT_LISTED`, `SECURITY_SUSPENDED`, `TRADED`, `NO_TRADE`, or `UNKNOWN`; it does not infer a trade from a missing row. `history()` reads nominal raw prices. `adjusted_history()` reads the separate research-adjusted artifact and never rewrites raw history. `DataPlatform.from_release()` reads the published security master, effective-dated company-name and ISIN histories, and queries Parquet prices, universe, liquidity, calendar, and status data. It also exposes `quality_tier`, `verified_start`, and `verified_end`. When `research_release_manifest.json` declares `RESEARCH_HIGH_CONFIDENCE`, strict mode uses that scoped research interval rather than broad raw archive dates. Effective-history lookups fail when zero or multiple rows match the requested date. Calendar results contain only official source-backed sessions; no weekdays are generated. Status queries return `ACTIVE_TRADING`, `SUSPENDED`, `DELISTED`, or `UNKNOWN_STATUS` intervals with evidence quality. Recovery scenarios are labelled `ZERO_RECOVERY`, `LAST_OBSERVED_PRICE`, or `DOCUMENTED_VALUE`; they do not overwrite a null canonical terminal value. The holdings queue API accepts downstream-held `security_id` values and returns terminal-event rows that need focused forensics. Use `DataPlatform.from_release(path, strict=True)` to reject dates outside the scoped verified date range; the default is permissive and returns available rows.
