# Downstream contract

Consumers must pin a release ID and manifest hash, then read published artifacts only: `security_master`, `symbol_history`, `company_name_history`, `isin_history`, `issuer_master`, `listing_episodes`, `daily_prices_raw`, `daily_prices_adjusted`, `corporate_actions`, `trading_calendar`, `trading_status`, `trading_status_intervals`, `active_universe_daily`, `liquidity_features`, and `terminal_events`.

The stable interfaces are `resolve_symbol(symbol, as_of_date)`, `company_name_at(issuer_id, as_of_date)`, `isin_at(security_id, as_of_date)`, `history(security_id, start, end)`, `adjusted_history(security_id, start, end)`, `active_on(as_of_date)`, `eligible_on(as_of_date, ...)`, `ranked_liquid_on(as_of_date, n, metric=...)`, `status_on(as_of_date)`, `sessions_between(start, end)`, and `terminal_recovery_scenarios(security_id)`. `history()` reads nominal raw prices. `adjusted_history()` reads the separate research-adjusted artifact and never rewrites raw history. `DataPlatform.from_release()` reads the published security master, effective-dated company-name and ISIN histories, and queries Parquet prices, universe, liquidity, calendar, and status data. It also exposes `quality_tier`, `verified_start`, and `verified_end` from the release manifest. Effective-history lookups fail when zero or multiple rows match the requested date. Calendar results contain only official source-backed sessions; no weekdays are generated. Status queries return `ACTIVE_TRADING`, `SUSPENDED`, `DELISTED`, or `UNKNOWN_STATUS` intervals with evidence quality. Recovery scenarios are labelled `ZERO_RECOVERY`, `LAST_OBSERVED_PRICE`, or `DOCUMENTED_VALUE`; they do not overwrite a null canonical terminal value. Use `DataPlatform.from_release(path, strict=True)` to reject dates outside the verified date range; the default is permissive and returns available rows.
